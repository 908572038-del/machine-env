# machine-env-cpp 环境查询规则

- 在回答涉及本机系统、shell、硬件能力、可用工具或工具路径的问题，以及选择本机可执行的构建/测试命令前，先检查项目文件中的实际要求，再查询当前环境；不要靠操作系统惯例、旧记忆或猜测补全。
- 需要操作系统、shell 能力、编码策略、权限或硬件（含 GPU 型号与显存）时调用 `get_system`；确认某个程序是否可用、版本与路径时调用 `get_tools`，并尽量用 `name` 只查需要的那一个，例如 `name: "cmake"`。
- 需要确认“装了哪些软件、装在哪里、哪个版本”时调用 `get_apps`；默认只返回总数，必须用 `filter` 指定关键字才会列出条目。`get_tools` 回答“能不能直接运行”，`get_apps` 回答“装了什么”，不要为同一个问题同时调用两者。
- 只有任务确实需要联网时才调用 `get_network`，并告知这会访问外部服务；它是唯一会发起外部请求的工具，`get_system` 不会联网。
- 能力字段带 `source`：`measured` 为实测、`unknown` 表示未验证。**不得把 `unknown` 当作支持**；若某能力未验证，不要据此断言可行或不可行。
- 只查询解决当前任务所需的信息。优先使用缓存结果；只有用户要求最新状态或缓存明显过期时才传 `refresh`。
- 根据 MCP 返回的实际路径和版本选择工具。工具未检测到时，明确说明缺失或给出已有替代方案，不要假设它已安装。
- 本 MCP 是只读探测器，不会替用户安装工具。未经用户明确要求或批准，不下载、安装或运行安装程序，也不擅自修改全局环境。
- 注意返回值中的约束提示（如 `不支持 &&`、`原生输出非 UTF-8`、`与PYTHON不同源`），据此调整命令写法，而不是先试一次再失败。
